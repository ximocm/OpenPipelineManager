# First run from scratch

[`first-run.json`](first-run.json) is the only sample pipeline. It creates its
own small input file, passes that output to the next step, and writes a report.
It needs a POSIX shell and `cat`, with no downloads, external scripts, or language
runtime. On Windows, use the POSIX shell provided by Git for Windows.

With the current application:

1. Choose **Project > Import pipeline** and select `examples/first-run.json`
   (or use **New pipeline** and build it). The source definition stays here; it
   becomes a named `.pipeline` document in the application library.
2. Choose **Project > New work**, pick that library pipeline, and select a fresh
   working directory outside this source repository, for example `opm-first-run`.
3. Keep the default `message` and `mode` values, review validation, then use
   **Run selected** with no steps selected to run both steps in dependency order.
4. Open `outputs/report.txt`. It should contain:

   ```text
   Hello from Open Pipeline Manager
   mode=demo
   ```

`Input/message.txt` is generated by the first step. Outputs, logs, and status
belong to this work folder. Creating a second work folder from the same library
pipeline gives an independent run; changing its message or report mode does not
change the other work or the library document.

Persistence is the consolidated format described in
[`docs/PIPELINE_STORAGE.md`](../docs/PIPELINE_STORAGE.md): one `.pipeline`
document per reusable pipeline and one `.pipeline-manager/run.json` per work
folder. Older project folders are not read or migrated.
